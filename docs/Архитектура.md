# Архитектура интеграции 1С и Bitrix24

## 1. Схема данных
В основе интеграции лежит Регистр сведений `СоответствиеИДБитрикс24`.
   Измерение `Объект` (тип составной, включает Справочники, Документы).
   Ресурс `ИД_Битрикс24` (тип Число).
   Этот регистр позволяет избежать записи в типовые справочники (что ломает модули типовой конфигурации) и служит кэшем для быстрого поиска связей.

## 2. Жизненный цикл сделки
[1С] Заказ Покупателя --> (создание) --> [Bitrix] Сделка (Стадия: Получен заказ)
|
v (основание)
[1С] Заказ на производство --> (поиск) --> [Bitrix] Сделка (Стадия: Передан в производство)
|
v (основание)
[1С] Реализация товаров --> (поиск) --> [Bitrix] Сделка (Стадия: Заказ отгружен)
|
v (регламентное задание)
[1С] Закрытие заказов --> (поиск) --> [Bitrix] Сделка (Стадия: Сделка завершена - WON)

## 3. Распределение по воронкам
Воронка (`CATEGORY_ID`) определяется на основе реквизита `Подразделение` в документе 1С:
*   Подразделения "АК", "ТУК" -> Воронка "Продажи АК/ТУК" (`CATEGORY_ID=3`).
*   Подразделение "Стакан" -> Воронка "Продажи Стакан" (`CATEGORY_ID=2`).

## 4. Складская интеграция
При записи `Реализации` (если настроено) в Bitrix24 создается документ типа `Оприходование` (`docType='S'`).
1. Вызов `catalog.document.add` — создание шапки.
2. Вызов `catalog.document.element.add` — добавление товаров.
3. Вызов `catalog.document.conduct` — проведение документа.
